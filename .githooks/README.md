# .githooks/

Все хуки проекта лежат здесь. Подключение одно, на репозиторий:

```bash
git config core.hooksPath .githooks
```

После этого git берёт хуки из этого каталога, а не из `.git/hooks`. Каталог обычный,
не скрытая магия агента: хуки запускает git, поэтому они работают одинаково и когда
коммитит агент, и когда коммитите вы руками.

## Что здесь сейчас

- `pre-commit.sample` — **заготовка, выключенная**. Это не хук: git запускает файл
  ровно с именем `pre-commit`, а `.sample` игнорирует. Заготовка нарочно неполная,
  рабочий хук вы делаете в днях 2–3.

## Что появится по ходу

| Файл | Что проверяет | Где |
|---|---|---|
| `pre-commit` | секреты в staged-изменениях + `php -l` | дни 2–3 |
| `guard-tests.sh` | что фикс не «починили» правкой теста | 2.16 |
| `protect-spec.sh` | что замороженную спеку не правят мимо процедуры | 3.7 |
| `scan-inputs.sh` | фильтр входов агентного цикла на инъекции | 3.26 |

Хук должен падать с понятным сообщением: что нашёл, в каком файле, как починить.
И помните: локальный хук обходится флагом `--no-verify`, поэтому те же проверки
дублируются в CI (`.github/workflows/pr-checks.yml`).
