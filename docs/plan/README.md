# docs/plan/

План реализации до первой строки кода: **как и в каком порядке**. Пишет его ваш
агент `planner` (1.4.1) — у него права на правку только здесь.

Имя файла: `plan_<ID задачи>.md` — в дне 1 это `plan_MILEAGE.md` (1.4.3);
для issue эпика в днях 2–3 — `plan_<EPIC-X>-NN.md`.

Разделы `plan_MILEAGE.md`:

1. **Файлы** — что и где меняем, по строке на файл. Всё, чего нет в списке, при реализации трогать нельзя.
2. **Шаги** — реализация по порядку.
3. **Тесты** — какие появятся; граничные значения отдельными строками (399999 / 400000 / 400001, пустой пробег).
4. **Риски** — что может сломаться рядом (в том числе существующая проверка `max_mileage_km`) и что не входит.

В конце — вопросы, на которые без заказчика не ответить.

Кода в плане нет, кроме сигнатур функций. В ДЗ.1 план сверяется со спекой и дополняется,
а на ревью готовый diff сверяется именно с этим файлом.
