# Учебная фича: защита от повторной заявки
Учебное требование, не регламент CarMoney.
Запретить вторую активную заявку одного клиента.
Критерии приёмки:
- Первая заявка создаётся.
- Повторная активная заявка возвращает HTTP 409.
- После закрытия предыдущей новая разрешена.
- Два одновременных запроса создают только одну активную заявку.
- Существующие тесты проходят.
Идентификатор клиента и статусы определить по проекту.
Если критического правила нет — сообщить блокер, не выдумывать.
Использовать существующий стек. Без коммита, push и деплоя.
