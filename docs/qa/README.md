# docs/qa/

Чек-листы приёмки: у каждого AC есть проверка, и человек решает, какие проверки стоят времени.

Имя файла: `acceptance_<ID задачи>.md` — таблица.

Колонки:

| CHK-… | AC | входные данные (синтетические) | ожидаемое решение и лимит | способ проверки | Оставить? |
|---|---|---|---|---|---|

- На каждый AC — строка Happy path и строка Edge case.
- Способ проверки: автотест (какой) / ручной `curl` / не проверяется (почему).
- Колонку «Оставить?» заполняет **человек**, с причиной.
- Не больше 25 строк: строки должны различаться классом данных, а не только числами.

Отдельно — 3–5 проверок «вне AC», которые сделал бы опытный тестировщик, с обоснованием.

Появляется в днях 2–3.
