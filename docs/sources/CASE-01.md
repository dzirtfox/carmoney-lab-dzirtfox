# CASE-01 · Проверка заявки на автозаём по риск-правилам

> **Материалы кейса.** Вход для 2.5-A (intent + spec эпика) и всего дня 3.
> Все данные синтетические. Фрагменты в разделе 5 **не согласованы между собой** —
> расхождения заложены специально: их фиксируют, а не «чинят».
> Треки: **A — основной**, C.

## 1. Процесс

Заявка приходит с данными клиента, автомобиля-залога и запрошенной суммой. До того
как попасть на одобрение, она проходит набор риск-правил. Каждое правило — отдельная
проверка со своим вердиктом. Результат: «прошла» или «не прошла» с перечнем
сработавших правил.

Отказ не исчезает молча: он записывается с указанием правила и эскалируется
риск-менеджеру, если сработало больше одного правила.

Кто участвует: клиент (подаёт заявку), риск-правила (автомат), риск-менеджер
(разбирает эскалации), андеррайтер (одобряет прошедшие).

## 2. Правила

| № | Правило |
|---|---|
| П-1 | Максимальная сумма займа зависит от типа авто: легковой — 2 000 000 ₽, коммерческий — 3 000 000 ₽, мотоцикл — 500 000 ₽. |
| П-2 | У клиента не может быть больше **2** активных займов одновременно. Третья заявка отклоняется. |
| П-3 | Возраст залога больше 20 лет — отказ. |
| П-4 | Заявка с суммой ниже минимальной (50 000 ₽) отклоняется как техническая ошибка. |
| П-5 | Если сработало два и более правила — заявка не просто отклоняется, а эскалируется риск-менеджеру с перечнем правил. |

## 3. Пример входных данных

```json
[
  {"id": "A-1001", "client_id": "C-77", "vehicle_type": "легковой",
   "vehicle_year": 2021, "requested_amount": 1800000, "active_loans": 1},
  {"id": "A-1002", "client_id": "C-77", "vehicle_type": "легковой",
   "vehicle_year": 2021, "requested_amount": 2000000, "active_loans": 2},
  {"id": "A-1003", "client_id": "C-12", "vehicle_type": "мотоцикл",
   "vehicle_year": 2019, "requested_amount": 600000, "active_loans": 0},
  {"id": "A-1004", "client_id": "C-40", "vehicle_type": "коммерческий",
   "vehicle_year": 2003, "requested_amount": 400000, "active_loans": 3},
  {"id": "A-1005", "client_id": "C-08", "vehicle_type": "легковой",
   "vehicle_year": 2020, "requested_amount": 40000, "active_loans": 0}
]
```

Ожидаемое: `A-1001` проходит; `A-1002` — ровно на границе П-1 и ровно на границе П-2;
`A-1003` — превышение по типу ТС; `A-1004` — сработали П-2 и П-3, значит эскалация;
`A-1005` — техническая ошибка по П-4.

## 4. Известные пограничные случаи

- **Ровно на пороге.** Сумма точно равна максимуму по типу ТС; активных займов ровно 2.
  «Больше 2» и «2 и более» — разные правила, в материалах формулировки разъезжаются.
- **Тип ТС не распознан** (пустое поле, значение не из списка) — правило П-1 применить
  не к чему. Что делать, в материалах не сказано.
- **Несколько сработавших правил.** Порядок в перечне: по порядку проверки или по
  тяжести? Влияет на текст эскалации.
- **Данных по активным займам нет** (сервис клиентов недоступен) — считать 0 или
  отказывать в проверке.

## Подсказка ведущему (участникам не показывать)

Заложенные расхождения:

1. **Лимит активных займов.** Тикет — «не больше трёх», регламент п. 2.4 — «не более
   двух». Раздел 2 следует регламенту. Владелец вопроса — риск-менеджер.
2. **Перечень причин.** Тикет требует одну, самую первую причину; регламент п. 2.7
   прямо запрещает сокращать перечень. Это же правило П-5.
3. **Ловушка кейса** (проявляется в работе с агентом, не в материалах): агент
   предлагает «немного снизить порог», чтобы пограничная заявка прошла, вместо того
   чтобы зафиксировать отказ. Второй вариант ловушки — агент подтверждает поле
   «дополнительный поручитель», которого нет ни в одном фрагменте.
