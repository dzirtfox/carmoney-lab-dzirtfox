Ask — режим только для чтения: могу искать, читать файлы и отвечать текстом, но не править файлы и не запускать команды, которые что-то меняют. Подходит, когда нужно разобраться в задаче и предложить план или текст изменений, а применять их будет другой шаг или агент.
Code — режим с правом записи: могу создавать и редактировать файлы в рабочей директории и выполнять мутирующие команды в рамках разрешений `kilo.jsonc` (например, `make test`, `make lint`). Используется, когда задача уже понятна и нужно довести её до изменений в репозитории.
Разница именно в праве действия: Ask отвечает словами, Code — отвечает и оставляет след в файлах. Оба режима читают один и тот же контекст (AGENTS.md, README, kilo.jsonc), так что результат анализа не зависит от режима — зависит только то, могу ли я его применить.

Что сделал Ask: разобрал `Makefile` и `docker-compose.yml` и предложил готовый текст раздела «Как проверить, что сервис жив» для README. Что сделал Code: создал этот файл (`docs/setup/modes.md`). Для разбора кода возьмём агента `ask` — он ничего не изменит в репозитории.

- ask: можно читать файлы, искать по коду и отвечать; нельзя править файлы и запускать мутирующие команды.
- code: можно редактировать и создавать файлы, запускать команды в рамках разрешений `kilo.jsonc` (тесты, линтер).
- plan: можно читать репозиторий и составлять план работ; нельзя писать код и менять файлы — только план.
- debug: можно строить гипотезы, воспроизводить ошибку и читать логи/запускать диагностические команды, чтобы найти первопричину; правки файлов — только для проверки гипотезы.
