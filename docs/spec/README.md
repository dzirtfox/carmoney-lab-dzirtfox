# docs/spec/

Требования и критерии приёмки: **что именно считается сделанным**.

Имя файла: `spec_<ID задачи>.md` — в ДЗ.1 это `spec_MILEAGE.md`, в днях 2–3 — `spec_CASE-NN.md`.

- Требования — `REQ-<задача>-NN` (`REQ-MILEAGE-01`), одно проверяемое утверждение со ссылкой на источник.
- Критерии приёмки — `AC-<задача>-NN` (`AC-MILEAGE-01`), формат Given / When / Then, у каждого ссылка на REQ.
- На каждое числовое правило — AC **на границе**: ровно на пороге и сразу за ним
  (для MILEAGE — 399999, 400000, 400001) и поведение при пустом или неизвестном значении.
- Раздел «Входит / не входит».
- Open questions из intent — у каждого статус «закрыт (чем)» или «перенесён (куда)».
- Требований, которых не было в intent, в спеке нет.

Слов «быстро», «удобно», «корректно» без числа или условия в спеке нет.
Как реализовывать — не здесь, это `plan/`.

Начиная с дня 3 спека эпика замораживается (`v1`, тег, `SPEC_SHA256`), и правка идёт
через PR с меткой `spec-change` и одобрением Хранителя спеки по CODEOWNERS.
