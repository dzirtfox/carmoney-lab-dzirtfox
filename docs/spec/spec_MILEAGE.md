# Spec: MILEAGE — правило «пробег авто не больше 400 000 км, иначе review»

> Источник требований: `docs/intent/intent_MILEAGE.md`, собран по интервью
> Grill Me 2026-10-01. Ссылки «вопрос N» — на нумерацию
> `docs/intent/grill_MILEAGE.md`; «код: …» — текущее состояние репозитория.
> Все данные синтетические.

## Входит / не входит

**Входит**

- Правило решения по пробегу: при пробеге больше 400 000 км решение `approve`
  понижается до `review`; границы срабатывания и взаимодействие с решениями
  по LTV (`review` и `reject` не меняются).
- Действие правила во всех сценариях расчёта решения: при сохранении заявки
  и при отдельном расчёте («только расчёт»).
- `approved_limit` при пониженном решении.
- Поведение при отсутствующем/пустом пробеге и при пробеге за границами
  валидации — без изменений (фиксируется, чтобы не сломать).

**Не входит** (источник — ответ в интервью, вопрос 5, если не указано иное)

- Задача LOAN-12 — LTV по возрасту авто (код: backend/config/rules.php:48-58).
- Изменение порогов LTV 60 / 85 (код: backend/config/rules.php:43-46) и
  границы валидации пробега 500 000 км (код: backend/config/rules.php:23).
- Правки фронтенда, БД и слоя хранения; поведение пустого поля пробега на
  фронте остаётся как есть (также ответ в интервью, вопрос 3).
- Пересчёт решений уже сохранённых заявок.
- Признак причины `review` в ответе (reason-коды).
- Синхронизация `docs/setup/code_map.md` — опциональный шаг после реализации.

## Требования и критерии приёмки

Общие условия для всех AC:

- «Валидная заявка» — заявка, проходящая существующую валидацию всех полей
  (код: backend/src/Domain/ApplicationValidator.php:24-83); в AC меняются
  только пробег и соотношение суммы к стоимости для задания зоны LTV.
- Зоны LTV (код: backend/src/Domain/DecisionEngine.php:32-40,
  backend/config/rules.php:43-46): approve-зона — LTV < 60; review-зона —
  60 ≤ LTV ≤ 85; reject-зона — LTV > 85.

### REQ-MILEAGE-01 — понижение approve при большом пробеге

Если пробег авто больше 400 000 км, решение по заявке — `review` вместо
`approve`. Число 400 000 — формулировка задачи в интервью; эффект — ответы в
интервью (вопросы 1–2). Граница — допущение, см. Open questions №1.

- **AC-MILEAGE-01** (REQ-MILEAGE-01, 02, 07). Given валидная заявка с LTV в
  approve-зоне и пробегом 399 999 км (400 000 − 1). When расчёт решения.
  Then решение `approve`, approved_limit = запрошенной сумме (код:
  backend/src/Domain/AssessmentService.php:39).
- **AC-MILEAGE-02** (REQ-MILEAGE-02). Given валидная заявка с LTV в
  approve-зоне и пробегом 400 000 км (ровно на пороге). When расчёт решения.
  Then решение `approve`, approved_limit = запрошенной сумме.
- **AC-MILEAGE-03** (REQ-MILEAGE-01, 07). Given валидная заявка с LTV в
  approve-зоне и пробегом 400 001 км (400 000 + 1). When расчёт решения.
  Then решение `review`, approved_limit = 0 (код:
  backend/src/Domain/AssessmentService.php:39).

### REQ-MILEAGE-02 — ниже порога решение не зависит от пробега

При пробеге не больше 400 000 км решение определяется только LTV. Источник:
ответ в интервью (вопрос 1).

AC: AC-MILEAGE-01, AC-MILEAGE-02 (выше).

### REQ-MILEAGE-03 — правило не ослабляет review и reject

Решения `review` и `reject` правило не меняет: LTV-каскад решает первым,
правило применяется после него. Источник: ответ в интервью (вопрос 2).

- **AC-MILEAGE-04** (REQ-MILEAGE-03). Given валидная заявка с LTV в
  review-зоне и пробегом 400 001 км. When расчёт решения. Then решение
  `review` (не `reject`), approved_limit = 0.
- **AC-MILEAGE-05** (REQ-MILEAGE-03). Given валидная заявка с LTV в
  reject-зоне и пробегом 400 001 км. When расчёт решения. Then решение
  `reject` (не `review`), approved_limit = 0.

### REQ-MILEAGE-04 — действие во всех сценариях расчёта

Правило действует при сохранении заявки и при отдельном расчёте («только
расчёт» на фронте). Источник: ответ в интервью (вопрос 4); сценарии — код:
backend/src/Http/ApplicationController.php:23,54.

- **AC-MILEAGE-06** (REQ-MILEAGE-01, 04). Given валидная заявка с LTV в
  approve-зоне и пробегом 400 001 км. When отправка заявки на сохранение.
  Then решение `review`, approved_limit = 0.
- **AC-MILEAGE-07** (REQ-MILEAGE-01, 04). Given та же заявка. When отдельный
  расчёт без сохранения. Then решение `review`, approved_limit = 0.

### REQ-MILEAGE-05 — отсутствующий пробег: поведение без изменений

Заявка без поля `mileage` или с `mileage = null` не доходит до расчёта
решения: ошибка валидации по полю пробега «Пробег от 0 до 500000 км» (код:
backend/src/Domain/ApplicationValidator.php:43-46), на HTTP — 422 с
перечнем ошибок (код: backend/src/Http/ApplicationController.php:30,61).
Источник: ответ в интервью (вопрос 3).

- **AC-MILEAGE-08** (REQ-MILEAGE-05). Given заявка без поля `mileage` или с
  `mileage = null`, остальные поля валидны. When расчёт решения (любой
  сценарий). Then ошибка валидации с ключом `mileage`, расчёт решения не
  выполняется, HTTP 422.

### REQ-MILEAGE-06 — пустое поле на фронте: поведение без изменений

Пустое поле пробега в форме уходит в запрос как 0 (код:
frontend/app.js:14) и обрабатывается как пробег 0 км. Источник: ответ в
интервью (вопрос 3); поведение — код.

- **AC-MILEAGE-09** (REQ-MILEAGE-06, 02). Given валидная заявка с LTV в
  approve-зоне, поле пробега на фронте оставлено пустым. When отправка
  (любой сценарий). Then в запрос уходит пробег 0 (код: frontend/app.js:14),
  заявка обрабатывается как пробег 0 км (нижняя граница валидации — код:
  backend/src/Domain/ApplicationValidator.php:44), решение `approve`:
  0 < 400 000, правило не срабатывает.

### REQ-MILEAGE-07 — лимит при понижении

При понижении решения до `review` approved_limit = 0; при `approve` —
запрошенной сумме. Источник: код:
backend/src/Domain/AssessmentService.php:39.

AC: AC-MILEAGE-01, AC-MILEAGE-03, AC-MILEAGE-06, AC-MILEAGE-07 (выше).

### REQ-MILEAGE-08 — вход правила: валидированный пробег

К расчёту решения пробег приходит из диапазона 0–500 000 (код:
backend/src/Domain/ApplicationValidator.php:43-46,
backend/config/rules.php:23); заявки с пробегом свыше 500 000 до расчёта
решения не доходят. Источник: код.

- **AC-MILEAGE-10** (REQ-MILEAGE-08, 01). Given валидная заявка с LTV в
  approve-зоне и пробегом 500 000 км (верхняя граница валидации, код:
  backend/config/rules.php:23). When расчёт решения. Then решение `review`
  (500 000 > 400 000), approved_limit = 0.
- **AC-MILEAGE-11** (REQ-MILEAGE-08). Given заявка с пробегом 500 001 км
  (500 000 + 1), остальные поля валидны. When расчёт решения (любой
  сценарий). Then ошибка валидации с ключом `mileage`, расчёт решения не
  выполняется, HTTP 422.
