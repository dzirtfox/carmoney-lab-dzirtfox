# carmoney-lab — учебный проект практикума М3

Учебный сервис **предварительной оценки заявки на заём под ПТС**. На нём вы три дня
работаете с кодинговым агентом: пишете постановку, план, код, тесты, ревью и выкатку.

Сервис принимает заявку (VIN, год выпуска, пробег, оценочная стоимость, сумма, срок),
считает LTV и возвращает решение `approve` / `review` / `reject`.

> **Все данные здесь синтетические.** Реальных заявок, ПДн и секретов CarMoney в проекте
> нет и быть не должно — ни в коде, ни в базе, ни в промптах агенту. Репозиторий публичный.

## Запуск за три команды

```bash
git clone https://github.com/<ваш-логин>/carmoney-lab-<ваш-логин>.git ~/carmoney-lab
cd ~/carmoney-lab && make up
make test
```

Форма: <http://localhost:8080/> · health: <http://localhost:8080/health>

Docker'а на ноутбуке нет? Тогда локально работают тесты и линтер
(`composer install && make test`), а форму для упражнения 1.6.3 ведущий даст на стенде — скажите ему.

| Команда | Что делает |
|---|---|
| `make up` | поднять сервис и базу |
| `make test` | прогнать PHPUnit |
| `make lint` | проверить синтаксис PHP |
| `make down` | остановить сервис |
| `make seed` | перезалить учебные данные |
| `make help` | список всех команд |

## API

| Метод | Путь | Зачем |
|---|---|---|
| `GET` | `/health` | проверка живости |
| `POST` | `/api/ltv` | рассчитать LTV и решение, ничего не сохраняя |
| `POST` | `/api/applications` | принять заявку, сохранить и вернуть решение |
| `GET` | `/api/applications` | список заявок (`?status=decided`) |
| `GET` | `/api/applications/{id}` | карточка заявки |

```bash
curl -X POST http://localhost:8080/api/ltv \
  -H 'Content-Type: application/json' \
  -d '{"vin":"XTA21099998765432","year":2019,"mileage":84000,
       "market_value":900000,"requested_amount":450000,"term_months":24}'
```

## Где искать задания

Все карточки упражнений, тайминг и доска прогресса — на экране практикума:
**<https://hakku.ai/carmoney-m3/>**

Номер задания читается как `день.блок.задание`: `1.3.2` — день 1, блок 3, второе задание.
Агент в практикуме один — **Kilo Code** (расширение для VS Code / Cursor / JetBrains),
как его поставить — [`docs/setup/tools.md`](docs/setup/tools.md).

## Как сдавать

Главное правило: **один блок = одна ветка = один PR.**

1. **Репозиторий должен быть публичным.** Вы создаёте его в 1.1.3: «Use this template» →
   Owner — ваш аккаунт → имя `carmoney-lab-<ваш-логин>` → **Public**. Приватный репозиторий
   доска не видит, и задания не засчитываются.
2. **В начале блока — новая ветка от свежего `main`.** Имя: `d1/<первое>-<последнее задание блока>-<логин>`.

   ```bash
   git switch main && git pull
   git switch -c d1/1.2.1-1.2.3-ivanov
   ```

3. **После каждого задания — коммит.** Коротко, что сделано:

   ```bash
   git add -A && git commit -m "1.2.1 modes"
   ```

4. **В конце блока — один PR в `main` своего репо.** Заголовок — диапазон заданий блока и
   название, например `[1.2.1–1.2.3] Интерфейс Kilo` (между номерами — длинное тире `–`):

   ```bash
   git push -u origin HEAD
   gh pr create --base main --title "[1.2.1–1.2.3] Интерфейс Kilo" --fill
   ```

   > **Один раз, до первого `gh pr create`:** `gh repo set-default <логин>/carmoney-lab-<логин>`.
   > У вас два remote (`origin` и `upstream`), и без этой команды `gh` может предложить открыть
   > PR в шаблон `carmoney-lab/carmoney-lab` — туда PR не открываем.

   Без терминала: после `git push` откройте свой репозиторий на github.com — появится жёлтая
   плашка с кнопкой **«Compare & pull request»**. Нажмите её, проверьте, что слева `base: main`
   **вашего** репозитория (не `carmoney-lab/carmoney-lab`), впишите заголовок-диапазон →
   **Create pull request**.

5. **Больше ничего делать не нужно.** Доска на <https://hakku.ai/carmoney-m3/> находит PR сама
   по заголовку и отмечает каждое задание из диапазона. Проверяющий оставит комментарий в PR.
   Мёржить PR можете сами, когда он проверен, — следующий блок начинайте от обновлённого `main`.

Ветки и заголовки дня 1:

| Блок | Ветка | Заголовок PR |
|---|---|---|
| 1 | `d1/1.1.1-1.1.4-<логин>` | `[1.1.1–1.1.4] Kilo Code` |
| 2 | `d1/1.2.1-1.2.3-<логин>` | `[1.2.1–1.2.3] Интерфейс Kilo` |
| 3 | `d1/1.3.1-1.3.4-<логин>` | `[1.3.1–1.3.4] Правила и границы` |
| 4 | `d1/1.4.1-1.4.3-<логин>` | `[1.4.1–1.4.3] Свой агент и план` |
| 5 | `d1/1.5.1-1.5.2-<логин>` | `[1.5.1–1.5.2] intent через Grill Me` |
| 6 | `d1/1.6.1-1.6.3-<логин>` | `[1.6.1–1.6.3] Инструменты` |
| 7 | `d1/1.7.1-t<NN>` — в командном репо `carmoney-lab/carmoney-lab-t<NN>` | `[1.7.1] Команда t<NN>` |
| ДЗ | `hw1/dz<N>-<логин>` | `[ДЗ.1] Пробег ≤ 400000`, `[ДЗ.2] Проверка на эмуляторе` |

Эталоны живут в upstream — из него только читаем, PR туда не открываем:

```bash
git remote add upstream https://github.com/carmoney-lab/carmoney-lab.git
git fetch upstream
```

Не успели на занятии — в классе не догоняем: доделайте в домашнем задании до 30.09 23:59,
**тем же PR блока** (досылайте коммиты в ту же ветку), критерии карточки те же.

## Что ещё лежит в репозитории

- [`AGENTS.md`](AGENTS.md) — паспорт проекта для агента: команды, конвенции, запреты. Kilo читает его сам.
- [`kilo.jsonc`](kilo.jsonc) — конфиг Kilo Code для проекта: модель, права (`permission`, 1.3.2), MCP (`mcp`, 1.6.3).
- `.kilo/agents/` — ваши агенты: `planner.md` и `scout.md` появятся в 1.4.1–1.4.2.
- [`.githooks/`](.githooks/) — git-хуки проекта; подключаются `git config core.hooksPath .githooks`.
- [`docs/agent-rules.md`](docs/agent-rules.md) — права и правила агента человеческим языком.
- [`docs/setup/`](docs/setup/) — как поставить Kilo Code и инструменты; сюда же складываются файлы дня 1.
- [`docs/`](docs/) — артефакты задач: plan, intent, spec, метрики, команда.

## Чего делать не нужно

- Вписывать настоящие ключи в `.env.example` и любые файлы репозитория.
- Запускать `scripts/reset_db.sh` — он удаляет все данные. Вернуть данные можно через `make seed`.
- Загружать в агента реальные данные CarMoney. Нужен похожий кейс — сделайте синтетику.
